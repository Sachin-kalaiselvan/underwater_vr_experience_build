# Technical architecture

## Stack (all versions checked against each other, not just "latest")

| | Version | Why this one |
|---|---|---|
| Unity | 6000.3.29f1 (6.3 LTS) | current LTS on the day this was set up (released 19 Nov 2026) |
| XR Interaction Toolkit | 3.3.2 | the version Unity 6.3 ships as its verified default |
| OpenXR Plugin | 1.16.1 | same, includes the Meta Quest feature + Touch / Touch Plus / Touch Pro profiles |
| Input System | 1.20.1 | same |
| XR Plugin Management | 4.6.1 | same |
| XR Core Utilities | 2.6.0 | same |
| URP | 17.3.0 | built into 6.3 |

The versions come from the editor's own bundled defaults (`com.unity.feature.vr` resolves to these in 6000.3.29f1), so they're the set Unity tested together.

Deliberately **not** used: `com.unity.xr.meta-openxr` (pulls in AR Foundation and composition layers, only needed for passthrough / scene understanding, ABYSS is fully virtual) and the Meta XR SDK (OpenXR covers everything here and keeps the project portable).

## Scenes

```
Bootstrap (build index 0)          MainExperience (loaded additively)
- XR Origin (XRI starter rig)      - seafloor + every environment model
- XR Interaction Manager           - 5 AreaZones (look of each area)
- EventSystem + XRUIInputModule    - EnvironmentManager, sun + caustics
- ABYSS_App (all systems + UI)     - interactables, destination markers
                                   - nav anchors, fish, marine snow
```

The rig and every system live in Bootstrap and never unload. The world is a separate scene, so a different environment (a client's own site, say) can be swapped in without touching the systems.

Both scenes are generated by `ABYSS > 2. Build content and scenes` (`AbyssSceneBuilder`). Layout is code, so it survives asset changes. The builder works out which way the terrain slopes toward the deep at build time instead of trusting Blender to Unity axis conversion.

| Assembly | What | Engine refs |
|---|---|---|
| `Abyss.Logic` | activity runner, settings data, progress store | **none** (pure C#, unit tested outside Unity) |
| `Abyss.Runtime` | everything that runs in the app | Unity + XRI + Input System + URP + TMP |

## Systems

Everything registers itself in a tiny service registry (`Services`) on Awake, so nobody uses `FindObjectOfType` at runtime and systems can be swapped or mocked. Core services use `DefaultExecutionOrder` so they exist before anyone asks for them.

| Area | Class | Job |
|---|---|---|
| Core | `ApplicationBootstrap` | loads the environment scene, logo time |
| | `ExperienceStateManager` | current state (Intro, MainMenu, Exploring, Activity, Inspecting, Paused, Completion) + mode (Exhibition / Guided). state only, no behaviour |
| | `ExperienceManager` | the flow: menus call into it, it calls everything else. also kiosk mode |
| | `SettingsManager` | `SettingsData` as json in PlayerPrefs, `Changed` event |
| | `ProgressTracker` | completions + discoveries. off by default between launches (exhibition kiosks want a fresh start) |
| | `IdleWatcher` | kiosk: resets when the headset comes off or nobody moves for 2 min |
| XR | `XRConfigurationManager` | floor tracking, foveation, refresh rate readout, recenter by moving the rig root (never the camera) |
| Interaction | `IAbyssInteractable` | the contract every interactable implements |
| | `InteractableObject` | default implementation on top of `XRSimpleInteractable` |
| | `InteractionManager` | registry by id, decides what a selection does, raises Selected / Discovered / Inspected |
| | `InteractionFeedback` | every outcome = visual label + sound + haptic. visual is never skipped |
| | `ObjectInspection` | brings an object in front of you, thumbstick rotates it, locks locomotion meanwhile |
| | `InformationDisplay` | the info panel, placed beside the object not over it |
| Activities | `ActivityDefinition` / `ActivityCatalog` | content as ScriptableObjects |
| | `ActivityRunner` (Logic) | step machine: Discover / Inspect / ReachDestination / Interact, any-order multi-target steps |
| | `GuidedActivityManager` | glue: feeds world events into the runner, lights markers, drives the HUD |
| | `DestinationMarker` | ring + beam on the floor, "reached" by head distance |
| Locomotion | `ComfortController` | maps settings onto XRI providers + the starter rig's input manager |
| | `NavigationManager` / `NavAnchor` | named spots, fade-teleport-fade jumps, Return to start |
| | `ScreenFader` | fade to water colour, never black |
| Environment | `EnvironmentManager` / `AreaZone` / `UnderwaterProfile` | blends fog, ambient (incl. SH probe), sun and caustics by where your head is. ambient has a floor so the deep stays navigable |
| | `FishSchool` | instanced, one draw call per school, keeps out of your face |
| | `GentleSway`, `CausticsAnimator`, `FollowHead` | cheap motion |
| UI | `UIFactory` / `UITheme` | all panels built from code, one look, 1 canvas unit = 1 mm |

## Adding content (what a client handover looks like)

- **New interactable:** put a model in the world, add a collider, add `InteractableObject`, point it at a new `InteractableDefinition` asset. No code.
- **New activity:** Create > ABYSS > Activity Definition, add steps that reference interactable / destination ids, add it to `ActivityCatalog`. No code. Bad activities (no steps, duplicate ids, empty targets) are rejected with a clear log line instead of breaking at runtime.
- **New step type:** add to `StepKind`, handle it in `GuidedActivityManager.OnSelected` or a new event hook. The runner already supports it generically.
- **Different interaction behaviour:** implement `IAbyssInteractable` on your own component.

## Comfort rules baked into code

- the camera transform is never written to. recenter and jumps move the `XROrigin` root.
- every location change fades. reduced motion makes the fade *slower*, not faster.
- panels are yaw-only, ~12 cm below eye level, 1.35 m away. HUD sits lower and only re-centres when it drifts 32° out of view.
- defaults: teleport on, smooth move off, snap turn 45°, vignette on.
- settings use big step buttons, no sliders (sliders need steady aim).
- a settings combination that leaves no way to move is fixed automatically unless "stay in place" was picked on purpose.

## Rendering budget (targets, not measurements)

- Vulkan, single pass instanced (multiview), 4x MSAA, no HDR, no depth/opaque copies, no realtime shadows, no post.
- one directional light with a cookie, no additional lights.
- one shader for nearly all geometry, zero textures except the cookie, SRP batcher + static batching for the world, GPU instancing for fish.
- fog + solid clear colour instead of a skybox.
- foveation 0.5 standard / 1.0 reduced, render scale 1.0 / 0.85.

None of this has been measured on a headset yet. See TESTING_PLAN.md.
